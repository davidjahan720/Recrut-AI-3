Bloc 01

Authentification & accès

L'application est accessible uniquement à l'équipe RecrutAI. Supabase Auth fournit un système email + mot de passe clé en main — rien à redévelopper.

01
Supabase Auth — email + mot de passe
Intégré nativement, aucun développement d'auth requis
Équipe RecrutAI

Ce que fait l'application

🔐
Login sécurisé

L'utilisateur saisit son email et mot de passe. Supabase Auth vérifie les credentials et retourne une session JWT gérée automatiquement.

🛡️
Protection des routes

Toutes les pages de l'app redirigent vers le login si aucune session active n'est détectée. La session persiste entre les visites.

Règles & contraintes

✓
Pas d'inscription publique

Les comptes sont créés directement dans le dashboard Supabase (onglet Authentication → Users → Invite user). Aucun écran d'inscription à développer.

✓
Pas de gestion de rôles

En V1, tous les utilisateurs connectés ont les mêmes droits. Pas de distinction admin / chargé / AM.

Bloc 03

Gestion des offres d'emploi

L'offre est l'objet central. Elle contient la description du poste qui sera transmise à l'IA pour le matching. C'est aussi sur la page de l'offre que l'équipe dépose les CV à analyser.

03
CRUD Offres + upload de CV
Créer une offre → déposer les CV à analyser
Équipe RecrutAI

Création de l'offre

＋
Informations de base

Titre du poste, localisation, type de contrat (CDI / CDD / alternance…), client associé.

📝
Description du poste

Texte libre décrivant le rôle, les responsabilités, les prérequis. C'est cette description qui est transmise à l'IA lors du scoring — elle doit être précise et complète.

📊
Statut de l'offre

Active : l'offre accepte les CV entrants. Clôturée : l'offre est archivée, l'upload de CV est refusé.

Paramètres de scoring

🎯
Seuil de qualification (paramétrable)

À la création de l'offre, l'équipe définit le score_threshold (0–100, défaut 60). Tout CV dont le score est ≥ à ce seuil déclenche la notification client. Modifiable à tout moment sur la fiche offre.

📋
Vue des candidatures

Depuis la fiche offre, on accède à tous les CV reçus avec leur score, statut et justification.

Bloc 04

Upload des CV & pipeline de traitement

Les CV n'arrivent pas via une interface candidat ni via une API externe. Ils sont déposés manuellement par l'équipe RecrutAI sur la page de l'offre, sous forme de fichiers PDF. Dès le dépôt, le pipeline se déclenche : stockage → extraction → scoring → notification.

04
Upload PDF + pipeline automatique
Supabase Storage + Edge Function (extraction unpdf + scoring Claude)
Équipe RecrutAI

Ce que fait l'utilisateur

①
Déposer des fichiers PDF

Sur la fiche offre, une zone de dépôt (drag & drop ou sélection) permet de charger un ou plusieurs CV au format PDF en une seule opération. Aucun autre champ à remplir : le nom et l'email du candidat seront extraits automatiquement par l'IA.

ℹ️
Feedback visuel par CV

Chaque CV uploadé apparaît immédiatement dans la liste avec un statut pending, puis se met à jour en temps réel : qualified, rejected, ou error.

Ce que fait le système

①
Stockage du PDF

Le fichier est uploadé dans Supabase Storage (bucket privé cvs). Le chemin est enregistré dans applications.cv_file_path.

②
Extraction du texte (unpdf)

L'Edge Function lit le PDF depuis Storage et en extrait le texte via la librairie Deno unpdf. Le texte est sauvegardé dans applications.cv_text.

③
Scoring Claude

Claude reçoit le texte + la description de l'offre. Il renvoie un JSON avec score, justification, candidate_name, candidate_email. La candidature est mise à jour avec tous ces champs.

Bloc 05

Scoring IA automatique

Le cœur de l'application. Un appel à Claude qui reçoit le CV et la description du poste, retourne un score et une justification, puis déclenche ou non l'email client.

05
Scoring Claude API
Texte extrait du PDF + system prompt + description offre → score + justification
Automatique

Étapes du scoring

①
Construction du prompt

La fonction assemble : le system prompt global (pré-rédigé, identique pour tous les CV) + le texte extrait du PDF uploadé + la description de l'offre ciblée.

②
Appel à Claude API

Claude analyse le matching CV / offre et extrait aussi les métadonnées du candidat (nom, email) depuis le texte du CV. Retourne un JSON structuré.

③
Mise à jour de la candidature

Les 4 champs (score, justification, candidate_name, candidate_email) sont écrits dans applications. Le statut passe à qualified (≥ seuil offre) ou rejected (< seuil offre).

Logique de qualification & notification

④
Comparaison au seuil de l'offre

Le score Claude est comparé à jobs.score_threshold (défini sur l'offre, 60 par défaut). Si score ≥ seuil → qualifié. Sinon → rejeté. Le seuil peut varier d'une offre à l'autre (ex. 75 pour un poste senior rare, 50 pour un volume important).

⑤
Email automatique (si qualifié)

Resend envoie un email à l'adresse notification_email du client associé à l'offre. L'email contient : nom du candidat, score, justification IA. Timestamp enregistré dans email_sent_at.

⑥
Gestion des erreurs

Si l'extraction PDF échoue, si Claude renvoie du non-JSON, ou si Resend retourne une erreur, la candidature passe en statut error avec le message d'erreur dans justification. Aucun email envoyé.

Format de réponse attendu de Claude :
{"score": 74, "justification": "Profil solide sur les critères techniques, expérience insuffisante en management d'équipe.", "candidate_name": "Sophie Martin", "candidate_email": "sophie.martin@email.com"}

Le system prompt impose ce format JSON strict. Le score est un entier entre 0 et 100. Si le nom ou l'email ne sont pas détectables dans le CV, Claude doit renvoyer null pour le champ concerné.

Dashboard & consultation

L'équipe RecrutAI consulte les résultats en lecture. Il n'y a pas de validation manuelle à effectuer — le système a déjà tout traité automatiquement.

📊
Liste des candidatures par offre

Triée par score décroissant. Chaque ligne affiche : nom du candidat, email, score, statut (qualifié / rejeté / en erreur), date de réception, justification IA, lien vers le PDF original dans Storage.

Ce qui n'existe pas (intentionnellement)

✕
Pas de validation manuelle

L'équipe ne peut pas "approuver" ou "refuser" un CV. La décision est prise par l'IA selon le seuil de 60. Lecture seule.

✕
Pas de renvoi manuel d'email

Les emails sont envoyés automatiquement au moment du scoring. Aucun bouton "renvoyer" en V1.

Données personnelles

RGPD & sécurité des CV

Un CV = données personnelles sensibles. Les règles appliquées par la plateforme pour rester conforme.

Règles appliquées

🔒
Bucket Storage privé

Le bucket cvs est en mode privé. Seuls les utilisateurs authentifiés peuvent lire un PDF, via des signed URLs à durée limitée (1h par défaut).

🕒
Durée de rétention : 6 mois

Les PDF et les textes extraits sont supprimés automatiquement 6 mois après réception (job planifié Supabase). Le candidat peut demander suppression immédiate via email RH.

🔑
Pas de clé API côté client

Les clés Anthropic et Resend ne sont jamais exposées au navigateur. Elles vivent uniquement dans les secrets de l'Edge Function.

Ce qui n'est pas fait en V1

✕
Pas de consentement candidat explicite

Hypothèse : les clients RecrutAI se chargent de recueillir le consentement avant de transmettre les CV. À formaliser avec un DPO avant passage en prod réelle.

✕
Pas d'anonymisation automatique

Le texte des CV est envoyé à Claude tel quel (incluant nom, email, téléphone). À évaluer selon les politiques Anthropic de traitement des données.
